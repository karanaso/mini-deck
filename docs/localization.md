# Localization

Mini Deck supports two interface locales: English (`en`) and Greek (`el`). Deck content, titles, uploaded images, generated participant names, exports, and collaboration state are not translated; only the interface chrome is localized. Two participants can use different interface languages on the same deck.

## Resolution order

Every document request resolves one locale before React renders:

1. A valid `lang` query parameter on a deck link (`en` or `el`).
2. A valid `mini-deck-locale` cookie (`en` or `el`).
3. The browser's `Accept-Language` header, sorted by quality value. Greek wins when it is the highest-priority supported language (`el` or `el-*`).
4. English, the default and fallback.

Share links generated by the editor include `?lang={en|el}` before the fragment. The proxy consumes a valid value, writes the locale cookie, and redirects to the same deck URL without `lang`; the browser preserves the fragment token across that redirect. The link language therefore wins over a stored or browser preference and becomes the remembered preference for later visits. Invalid or missing values are ignored.

The parameter is presentation-only: it never changes the deck ID, fragment token, role, permissions, collaboration data, or exported content. Deck routes do not use locale-prefixed paths. If cookies are blocked, the deck still opens, but the language hint may fall back to `Accept-Language` after the parameter is consumed.

Invalid cookies and malformed language headers are ignored. Locale is not written into Yjs or awareness data; only the `lang` query hint and the locale cookie carry the preference.

The cookie is a presentation preference, not an authorization input:

```text
name: mini-deck-locale
value: en | el
path: /
max-age: 31536000
samesite: Lax
secure: only on HTTPS
httponly: false
```

The client writes it when the user switches languages. The proxy writes it when a deck link carries a valid `lang`. If cookies are blocked, the switch still applies to the current tab but is not persisted.

## Server and client boundaries

```text
apps/web/src/lib/i18n/config.ts       Supported locales, cookie, Accept-Language parser
apps/web/src/lib/i18n/server.ts       Request-scoped getLocale() using cookies()/headers()
apps/web/src/proxy.ts                 Deck-link language handoff, cookie, clean redirect
apps/web/src/lib/i18n/dictionaries/   English source of truth and Greek translation
apps/web/src/lib/i18n/dictionaries.ts Lookup, typed keys, interpolation, plural selection
apps/web/src/lib/i18n/format.ts       Intl-based relative time, dates, numbers
apps/web/src/components/i18n/         LocaleProvider and LocaleSwitcher
```

- The root layout is dynamic: it reads the cookie and header, renders `<html lang={locale}>`, and passes `initialLocale` to `LocaleProvider`. `generateMetadata` uses the same locale for the browser title and description.
- The proxy handles deck links with a valid `lang` before the layout request: it sets `mini-deck-locale`, removes `lang` from the URL, and returns a `307` redirect. The follow-up request uses the cookie, so the first server render is already in the link's language.
- `LocaleProvider` exposes `locale`, `t(key, params)`, `tCount(baseKey, count)`, and `setLocale(next)`. Switching updates the context immediately, sets `document.documentElement.lang` and the document title, persists the cookie, and calls `router.refresh()` so server-rendered content and metadata catch up.
- `router.refresh()` preserves client state and does not remount the editor. A language switch keeps the Yjs document, undo history, selection, current slide, open dialogs, and collaboration connection intact.
- Both dictionaries are imported by the client provider so switching works instantly and offline. The dictionaries are in the local client chunk, not duplicated in the server RSC payload.

## Dictionaries

English (`dictionaries/en.ts`) is the source of truth. Greek (`dictionaries/el.ts`) is typed as `EnglishDictionary`, so a missing or extra key fails `tsc`. Keys are flat and namespaced:

```text
common.*        Shared actions
landing.*       Landing page and recent decks
deckShell.*     Loading, invalid-link, and error states
editor.*        Top bar, slides, toolbar, style panel, zoom, feedback
share.*         Share dialog
participant.*   Display-name dialog
presentation.*  Presentation overlay
errors.*        API/operation errors
format.*        Pluralized counts
metadata.*      Browser title and description
a11y.*          Accessibility names
```

Use `t("namespace.key")` for plain strings. Interpolation replaces `{name}` placeholders:

```ts
t("landing.recent.open", { title: "Launch plan" });
```

Use `tCount("format.elements", count)` for pluralized counts. It selects `<baseKey>.one` or `<baseKey>.other` with `Intl.PluralRules`. Both current locales use `one`/`other`; an unhandled category falls back to `.other`.

Never concatenate English fragments or add user-visible copy directly to JSX. Add an English key, add the Greek key, and use `t`. React escapes all dictionary values; do not put HTML in messages.

## Greek style

- Direct, friendly tone, mostly second-person singular for actions and instructions.
- Prefer gender-neutral phrasing. Avoid constructions that require a gendered adjective or participle when a neutral alternative exists.
- Use Greek punctuation (`·`, `;` for the Greek question mark) and sentence case.
- Keep `Mini Deck`, `PNG`, `PDF`, `URL`, key names, and keyboard symbols unchanged.
- Keep the product term `deck` as a Latin loanword; translate slides, links, controls, and actions normally.

## API and operation errors

API envelopes keep their existing stable shape:

```json
{
  "error": {
    "code": "image_too_large",
    "message": "Images must be 10 MB or smaller",
    "details": { "maxMb": 10 }
  }
}
```

`message` is for API consumers and logs. The web client never renders it. `lib/api-error.ts` parses `code`/`details` into an `ApiError`, and messages are selected from `errors.api.<code>`, with `errors.api.generic` for unknown codes and `errors.api.network` for failed requests. Optional `details` values fill interpolation placeholders.

Client-side operations use `AppError` with a dictionary key (for example `errors.image.tooLarge` or `errors.export.image`). Keep the technical exception in `cause` for logging; do not display it.

## Formatting

- Relative timestamps: `Intl.RelativeTimeFormat` (`τώρα`, `πριν από 5 λεπτά`, `χθες`). English keeps its existing compact copy (`Just now`, `5m ago`, `2h ago`, `3d ago`) so the English experience stays unchanged.
- Dates older than the relative window: `Intl.DateTimeFormat` (Greek) or the existing English `toLocaleDateString("en-US")` fallback.
- Counts and plurals: `Intl.PluralRules`.
- Numbers: `Intl.NumberFormat`.

Formatting helpers accept the locale explicitly so they are testable without React.

## Adding or changing a string

1. Add the English key to `dictionaries/en.ts` in the appropriate namespace.
2. Add the Greek translation to `dictionaries/el.ts` with the same placeholders.
3. Use `t(key, params)` or `tCount(baseKey, count)` in the component.
4. Add or update a unit test when the string has interpolation or plural behavior.
5. Run `pnpm --filter @mini-deck/web typecheck` and the i18n tests.

`apps/web/test/i18n.test.ts` enforces key parity, non-empty values, matching placeholders, plural output, and locale-aware formatting.

## Coverage checklist

When adding UI, check both locales for:

- Visible labels, buttons, headings, help text, and empty states.
- Toasts, validation errors, export progress, and failure messages.
- `aria-label`, `title`, screen-reader text, dialog close labels, and status text.
- Singular/plural counts and relative/absolute timestamps.
- Server API errors mapped by code, not raw English `message`.
- Long Greek strings in the top bar, toolbar, style panel, share dialog, presentation help, and landing cards.
- Deck content, titles, images, exports, participant names, and collaboration fields remain untouched.

## Adding a future locale

1. Add the locale code to `SUPPORTED_LOCALES` and its formatter tag/label in `config.ts`.
2. Add `dictionaries/<locale>.ts` typed as `EnglishDictionary`.
3. Register it in `dictionaries.ts`.
4. Add its `Intl` locale tag and any plural keys required by its rules.
5. Add locale coverage to the unit tests and Playwright suite.
6. If dictionaries grow large, lazy-load the inactive dictionary; verify instant switching and offline behavior.

```bash
  apps/web/test/i18n-server.test.ts apps/web/test/api-error.test.ts

```

The Playwright config pins English for existing tests. Greek coverage sets the browser locale or the locale cookie explicitly. The Greek axe test covers landing, editor, viewer, and presentation. The layout test checks desktop and narrow widths for horizontal overflow; this is an automated guard, not a substitute for visually reviewing every new Greek string.

## Bundle size

The production build places both dictionaries and the provider in one client chunk. At the time of this change the chunk containing the Greek strings measured about 66 KB raw / 18 KB gzip; the dictionary source files total about 32 KB. This is acceptable for two locales. Revisit lazy loading if more locales are added.

## Environment note

`scripts/with-db.sh` reads the port from `DATABASE_URL` and starts PGlite on that port, so `pnpm test:integration` and `pnpm test:e2e` work with the repository's default `5433` URL as well as a CI `5432` service. Keep the database running or let the wrapper start it.
